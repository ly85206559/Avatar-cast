# AvatarCast 可复用口播风格调研

调研日期：2026-11-01。状态：产品设计建议，尚未实现下述配方和语音对齐能力。本次只研究和记录，不调用视频生成服务、不发布视频。

## 结论

建议把“选一个颜色风格”升级为“用户说目的，系统选成片配方”。先形成六种默认配方设计：**单卖点推荐、单知识点讲解、避坑清单、温暖共鸣、成长故事、个人品牌／本地服务**，首轮实现与验证先选知识、共鸣、单卖点三个代表。另外六种保留为增强路线，按类型补真实素材、来源或角色。用户通常只交一张有权使用的人像和一句话；缺少会改变真实性的商品、经历或现场素材时，再补问一个必要问题。

一张人像足以承担讲解、观点、陪伴和自我介绍；它不能提供真实商品演示、实际使用效果、店内环境或客户见证。应把“能生成一条数字人口播”与“足以制作带货实证视频”分开。包装不能替代证据。

这里研究的是可复用内容结构，不是“保证爆款”的模板。官方材料提供创作原则和案例，不能证明我们的实现、特定中文受众或某个账号一定有效。

## 1. 当前实现与目标之间的差距

本地代码快照：`aec710da81332320ab375187034060ddad2b0e89`。

- [presentation.py](../src/dhp/presentation.py) 的 `clean / promo / explainer` 主要控制标题板位置、颜色和字幕外观；`auto` 按少量关键词选择。它们还不是叙事、分镜或逐句强调的完整配方。
- [native_assembly.py](../src/dhp/native_assembly.py) 明确将字幕时间标为按片段容器时长估算，仍需人工复核，尚不能声称逐词同步。项目中存在其他 ASR 组件，不等于这条模型原生口播路线已经接入语音对齐。
- [native.py](../src/dhp/native.py) 当前单片段允许 1–15 秒；[make.py](../src/dhp/make.py) 默认每段 10 秒。应先支持“一个卖点／一个知识点／一个情绪瞬间”的 mini，再扩展多片段。不能把三个完整卖点硬塞进 10 秒。
- 多片段原生生成的音色、身份和表演连续性仍需实际验证。拼接成功不是连续性合格的证明。
- 当前这条路线没有按语义节拍调速或自动改变已说对白的能力。叙事和语气首先依靠 Skill 文案与生成提示；对已有原片执行 `restyle` 不会重写声音或台词。
- [components.py](../src/dhp/components.py) 已声明 `PriceTag(value)`、`FactCard(claim, evidence)`、`MapRoute(places)`、`QuoteCard(quote, source)` 及缺参数验证，可作为后续少量卡片的复用契约；这不等于 `make` 原生流程已经渲染它们。

因此，下面的配方都应分别记录三个维度：

| 维度 | 回答的问题 | 示例 |
| --- | --- | --- |
| 内容目的 `purpose` | 让观众得到什么 | 理解知识、判断商品、获得共鸣、认识服务 |
| 叙事结构 `format` | 按什么顺序说 | 问题→答案→解释；困境→转折→感悟 |
| 视听处理 `treatment` | 用什么方式呈现 | 极简字幕、步骤卡、柔和留白、实物画中画 |

“知识分享”不等于蓝色，“带货”不等于黄色，“情感”也不等于加一首伤感音乐。同一结构可以换外观，同一外观可以服务多个目的。这是我们的产品设计拆分。

## 3. 成本与素材标记

所有方案都要先取得基础数字人口播。现有账号可能消耗订阅额度或生成次数；只有核实具体账号、入口、配额和任务计划后，才能判断某次是否额外付费。

| 标记 | 额外工作与费用来源 |
| --- | --- |
| L：本地包装 | 在已完成原片上做字幕、标题、步骤卡、轻微裁切和音量处理；无需再次请求生成模型，但仍使用本地算力、存储与运行时间 |
| M：真实素材增强 | 用户补充商品图、录屏、现场视频或证据，在本地合成；素材本身的拍摄、采购、授权可能有成本 |
| X：可选外部服务 | 另外调用 ASR、配音、音乐授权、素材库或生成画面；依具体服务和授权计费，不预设价格，也不自动开启 |

以下“费用 L / M”只描述基础口播以外的包装成本。多片段通常意味着更多生成任务／额度；“已有订阅”不等于无限免费。背景音乐默认关闭；有合适的已授权音乐才启用。已有原片切换包装优先走本地重剪。

## 4. 首发六种：一句话即可自动选择

共同默认：一段只承诺一个核心信息，保持授权人像身份，字幕清楚，片头直接进入内容，结尾不强行“点赞关注”。下列 mini 节拍可压缩或合并，不要求每个节拍都是独立镜头。

| 首发配方 | 开头骨架（产品建议） | 仅人像＋一句话能否做 |
| --- | --- | --- |
| A 单卖点推荐 | “如果你常遇到【场景】，可以看看【一个卖点】。” | 有条件：可做已确认事实的介绍；真实商品／使用演示需产品素材 |
| B 单知识点 | “【概念】到底是什么？简单说就是……” | 通常可以：需保证知识正确，具体数字与新事实另核查 |
| C 避坑清单 | “第一次【做某事】，先检查这一个地方。” | 原则说明可以；实际操作教程需过程素材 |
| D 温暖共鸣 | “最近总觉得【具体处境】？先别急着否定自己。” | 可以：不伪造经历、留言或治疗效果 |
| E 成长故事 | “那次【已确认的小挫折】，让我后来学会了……” | 有条件：须有用户确认的真实故事，或明确标注虚构 |
| F 个人品牌／本地服务 | “如果你在【已确认地区】需要【服务】，我是……” | 有条件：只说已确认身份／服务；作品、环境与客户证言另需素材 |

### A. 单卖点推荐：这个东西帮谁解决什么

- **适合目的／输入**：产品或服务介绍。“帮我介绍这款带手提环的保温杯，主打通勤方便。”
- **叙事**：mini＝一个场景痛点→一个有依据的卖点→适合谁；较长版＝痛点→演示／依据→适用条件→下一步。可借用问题与解决方案的结构，但不夸大焦虑。
- **包装**：开场一张短问题卡；卖点出现时只强调一个关键词。有真实商品图再加商品卡／特写，口播说到哪里就展示哪里；正常偏明快语气，音乐可省。
- **可选 CTA**：“查看规格”“了解适用型号”；没有真实优惠或截止时间，不生成稀缺话术。
- **最少素材／人像够不够**：人像＋已确认商品／服务事实可以做介绍。要称为实物演示、使用评测或带货效果证明，必须补真实商品图／视频及相关依据；不能把虚拟主播说“我用了一个月”当成真实体验。
- **工作／费用**：介绍版 L，商品展示 M；新增生成商品镜头属于 X，不能替代实证。官方工作表确实把企业介绍与实物展示联系起来，产品页也将评测和演示列为不同内容形式。[TikTok 工作表](https://ads.tiktok.com/business/library/Storytelling_Formats_One_Pager_SMB.pdf)、[TikTok Shop 风格指南](https://seller-us.tiktok.com/university/essay?knowledge_id=4401155330393899)。

### B. 单知识点讲解：一个问题，一次讲明白

- **适合目的／输入**：科普、概念解释、FAQ。“用一句大白话解释复利。”
- **叙事**：mini＝问题→一句答案→一个小例子；较长版＝常见误解→正确解释→例子／适用边界→一句结论。对复杂话题缩小问题，不只缩短语速。
- **包装**：开头显示问题；回答时出现一个定义卡，类比可用本地图形，不堆无关素材；字幕强调名词与结论，语气清楚自然。
- **可选 CTA**：“下一条解释哪个词？”或无 CTA。
- **最少素材／人像够不够**：一般概念可以。数值、时效性事实、专业主张需可核查来源；图表要有真实数据。涉及操作结果的讲解不能伪装成已演示。
- **工作／费用**：L；额外语音识别或插图服务可选 X。将一个独立实用点作为短片是官方指南支持的方向，具体卡片结构是本项目建议。[YouTube Shorts 指南](https://blog.youtube/creator-and-artist-stories/transitioning-your-long-form-content-to-youtube-shorts/)。

### C. 避坑清单：看完能做一件更好的事

- **适合目的／输入**：经验分享、检查要点、选择标准。“给第一次租房的人讲一个看房避坑点。”
- **叙事**：mini＝一个常见错误→一个检查动作→原因；较长版＝明确对象→两至三个有先后顺序的要点→回顾。10 秒版标题必须写“一个要点”，不能挂“三个坑”却只讲一个。
- **包装**：用单张“先检查什么”卡或按语音递进的编号卡；当前步骤高亮，其他步骤减淡；偏干练语气，小提示音可选，不每个字都跳动。
- **可选 CTA**：“下次照这个检查”；收藏提示可选。
- **最少素材／人像够不够**：抽象检查原则可以；实际修理、做饭、软件点击等操作需要真实过程素材或降为口头提醒。
- **工作／费用**：L；实际示范 M。清单是我们的组织方式，官方支持的是有用信息及可独立理解的实用步骤。[TikTok 内容质量标准](https://ads.tiktok.com/resources/help/article/about-tiktoks-content-quality-standard-for-creator-commercial-content?lang=en-GB)、[YouTube Shorts 指南](https://blog.youtube/creator-and-artist-stories/transitioning-your-long-form-content-to-youtube-shorts/)。

### D. 温暖共鸣：先说中一个具体处境

- **适合目的／输入**：陪伴、鼓励、情绪表达。“安慰一下最近觉得自己进步太慢的人。”
- **叙事**：mini＝一个熟悉处境→理解／重新看待→一个很小的行动；较长版＝处境→具体感受→换个角度→温柔收束。避免凭空诊断观众或承诺治愈。
- **包装**：留白、低密度字幕，关键句完整停留；轻微推近可以，避免频繁跳切；语气温暖，有自然停顿。无音乐也成立，有已授权音乐时压低到不抢语音。
- **可选 CTA**：一句开放提问，或仅以安慰句结束；默认不附带购买行动。
- **最少素材／人像够不够**：可以，前提是不冒用真实人物经历、留言或心理治疗效果。
- **工作／费用**：L。官方区分真实情感连接与空泛煽情；“具体处境＋小行动”是我们将其落地的设计。[TikTok 内容质量标准](https://ads.tiktok.com/resources/help/article/about-tiktoks-content-quality-standard-for-creator-commercial-content?lang=en-GB)。

### E. 成长故事：一个转折，留下一个感悟

- **适合目的／输入**：个人经历、创业感悟、故事分享。“把我第一次演讲失败后继续练习的经历讲成短片。”
- **叙事**：mini＝一个受挫瞬间→一次小转变→感悟；较长版＝起点→阻碍→行动→结果→感悟。故事若超时，优先选一个瞬间，保留因果。
- **包装**：起点／转折／现在三类短标记；转折时才改变画面裁切或文字状态；情绪随内容发展，避免整段激昂配乐。mini 通常两次文字变化就够。
- **可选 CTA**：询问相似经历，或无 CTA。
- **最少素材／人像够不够**：讲述可以，但真实故事事实须由用户提供或确认；泛用鼓励改用 D。虚构故事须明确标注，不能让数字人冒充有该经历的真实用户；旧照片只是可选增强。
- **工作／费用**：L，历史素材增强 M；长版多个生成片段要额外评估连续性和额度。小故事和情绪瞬间具有短片适配性是官方访谈的启发，三段标记是本项目设计。[YouTube Shorts 深度访谈](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/)。

### F. 个人品牌／本地服务：让合适的人知道你能帮什么

- **适合目的／输入**：自我介绍、店主招呼、服务说明。“我是杭州的宠物摄影师，想让附近养猫的人认识我。”
- **叙事**：mini＝服务谁→解决什么→一句邀请；较长版＝目标人群→具体方法／真实作品→差异与边界→预约方式。
- **包装**：简短姓名／角色条，服务信息卡；有真实作品才做作品画中画。位置、营业时间和联系入口只用已确认信息；语气亲切、可信，保留品牌字体与色彩。
- **可选 CTA**：一个实际可用的预约／咨询入口，不同时塞电话、二维码、三个账号。
- **最少素材／人像够不够**：介绍服务可以；门店环境、作品、资历、客户评价需要真实材料。没有现场素材就不叫“带你探店”。
- **工作／费用**：L，作品／现场增强 M。企业介绍和清楚行动指引有官方依据；中文本地服务版是我们的应用建议。[TikTok 工作表](https://ads.tiktok.com/business/library/Storytelling_Formats_One_Pager_SMB.pdf)、[Google ABCD 手册](https://www.thinkwithgoogle.com/_qs/documents/15987/ABCDs_PDFPlaybook_April2022_Final.pdf)。

## 5. 六种增强候选：按类型补素材、来源或角色

这些配方值得提供，但不应伪装成“一张人像自动获得所有证据”。选中后先检查现有材料，缺什么就集中问什么；允许用户改为首发六种中的可行版本。

| 候选与目的 | mini／较长版叙事 | 画面、字幕、声音与可选 CTA | 最少素材；人像单独是否可行 | 工作／费用 |
| --- | --- | --- | --- | --- |
| G. 真实对比／前后变化：辅助选择或解释效果 | mini 只比一个维度；长版讲条件→同条件对比→差异→适合谁 | 两边同尺度呈现，标明条件和数据来源；字幕突出差别，语气客观；CTA 可为“按你的需求选” | 对比双方的真实图／视频／数据；效果前后需真实记录与条件。仅人像不可做实证，可降为选购原则 | M；额外拍摄、外部服务为 X |
| H. 开箱／单动作演示：展示实物和使用过程 | mini 一个真实揭示／动作；长版期待→开箱→细节→一次使用→结论 | 实物为主，主播可小窗；动作与讲解相符，保留真实操作声，字幕标步骤；CTA 可为“查看尺寸／配件” | 连贯的真实开箱或使用素材；仅人像不可。不能凭生成人手／产品变化证明功能 | M；复杂新拍或付费素材为 X |
| I. 软件／网站教程：让人完成一个任务 | mini 一个点击／结果；长版问题→前提→步骤→结果→常见失败 | 真实录屏占主画面，局部放大／光标指示；逐步字幕，清楚旁白；CTA 可为“按步骤试一次” | 对应版本、权限和页面的录屏或截图，验证过的步骤；仅人像只能口头说明 | M；若另调工具、ASR 或配音则 X |
| J. 实地导览／探店：让人了解真实场所 | mini 一个区域亮点；长版怎么到→场景→细节→适合谁→提醒 | 真实全景／细节与地址卡，字幕区分事实和感受；可留环境声；CTA 可为实际导航／预约 | 获准使用的现场视频／照片、地点与营业信息；仅人像不可称现场体验 | M；拍摄／授权另算 |
| K. 新闻／新功能解读：解释一个变化及影响 | mini 已核实事实→对谁有影响；长版发生什么→依据→影响→不确定性→行动 | 标日期和来源，资料卡／截图与解说对应；资讯语气，避免煽动性音乐；CTA 可为“查看原始公告” | 最新一手公告或文件、明确时间与引用权；人像＋已核实文本可以做解读，不能伪造新闻画面 | L 或 M；额外数据／媒体服务为 X |
| L. 双角色问答／轻喜剧：用误解与回应讲清楚 | mini 一个问答或反转；长版设问→冲突→澄清→回扣 | 清楚标角色，交替对白，字幕分角色；声音切换与笑点停顿；CTA 可为真实问题征集 | 两个授权角色／声音，或明确标注单人分饰；仅一张图只适合降为单人 FAQ。不可捏造真实用户留言 | 多角色生成与声音一致性需验证；L 仅可包装已有片段，新增生成属额外任务／可能 X |

G、H 的类型直接受到官方评测、前后对比、开箱和教程分类启发，但真实性要求不能省略。[TikTok Shop 风格指南](https://seller-us.tiktok.com/university/essay?knowledge_id=4401155330393899)。I 的界面讲解也在官方企业介绍工作表中出现。[TikTok 工作表](https://ads.tiktok.com/business/library/Storytelling_Formats_One_Pager_SMB.pdf)。J、K、L 是我们基于资料表达、场景与叙事形式提出的候选；本调研没有证明它们比其他形式更容易获得流量。

## 6. 对“懒人流程”的具体建议

用户入口仍只保留：“上传照片＋说一句你要讲什么”。首次设置账号与授权在安装／接入阶段处理，不让每条视频重新填写模型参数。成片前只展示一行可理解的选择，例如：“知识讲解 · 约 10 秒 · 一个知识点 · 本地加字幕”。

可在后续实现一个更贴近带货用户的简化：首次选定授权人像后，仅在本地记为常用形象；以后“补一张真实产品图＋一句话”即可复用人像。此能力尚未实现；当前 `image` 参数仍是人像参考，不能直接替换成产品图。常用形象与私人素材不随开源仓库公开，不需要为此先建立账号或身份平台。

推荐决策顺序：

1. **识别目的与已有事实**：推荐／推广→A；解释／为什么→B；步骤／别踩坑→C；安慰／共鸣→D；经历／变化→E；介绍我／我们店→F。不要仅凭关键词自动采信商品效果、身份和经历。
2. **先看素材能否支撑**：真实演示、前后效果、界面操作、实地体验优先检查素材。缺素材可改成口头介绍／原则说明；如果用户明确要实证视频，就必须补素材，不能默默造画面。
3. **再缩小信息量**：默认 mini，一个观点。若一句请求包含三点，先选择最有价值的一点并在预览说明；用户明确要完整清单再计划多片段，并提示任务数量／额度。
4. **自动给可审阅的短文案和包装预览**：默认标题、字幕、语气、可选 CTA 都已填好；用户可以只说“更温柔”“更像推荐”“换成知识分享”。避免要求用户理解 `format`、ASR、ASS 或供应商参数。
5. **更换外观优先复用原片**：标题、字幕、布局、音乐音量的修改本地完成。要改口播、人物表演或重做片段时，才重新评估生成任务与费用。

模糊的一句“帮我做条口播”默认进入中性短介绍；不要擅自补身份、商品、故事或强推销售 CTA。能从已授权上下文取得的信息就复用；确实影响真实性的缺口才补问。

## 7. 配方数据与时间轴的最小提案

第一期不必搭建通用分镜引擎或开放十几项用户设置。保留现有 Python 核心＋薄 Skill 入口，先把六个配方作为少量可读规则，并让现有 `clean / promo / explainer` 继续承担外观基础。以下结构是提案，不是当前 CLI 已支持的接口：

```json
{
  "recipe_id": "knowledge_one_point",
  "purpose": "teach",
  "format": "question_answer_example",
  "treatment": "clear_cards",
  "mode": "mini",
  "target_duration_sec": 10,
  "title": "复利是什么",
  "speech_units": [
    {"id": "s1", "text": "复利就是利息也会继续产生利息。"},
    {"id": "s2", "text": "就像雪球越滚，下一次带上的雪也越多。"}
  ],
  "beats": [
    {"id": "answer", "speech_ids": ["s1"], "overlay": "利息也生息"},
    {"id": "example", "speech_ids": ["s2"], "overlay": "像滚雪球"}
  ],
  "required_assets": ["authorized_portrait"],
  "optional_assets": [],
  "cta": null,
  "music": "off",
  "timing_status": "planned_not_aligned"
}
```

处理阶段及时间原则：

| 阶段 | 输出 | 时间与验证原则 |
| --- | --- | --- |
| 意图→事实／素材检查 | 目的、配方、已知／未知事实 | 不生成未提供的证言、参数、地址、优惠 |
| 短文案→语义节拍 | 可独立成立的句子及对应画面动作 | 10 秒 mini 可先按“首个短句建立问题；主体讲一个点；末句收束”估算，不固定照抄 3–6 秒开头 |
| 原生生成／取得原片 | 实际视频、实际语音 | 计划长度不是实说时长；检查漏词、改词、尾句和多段连续性 |
| 语音转写／对齐（待实现于此路线） | 实际语句边界、置信度 | 有语音时间戳后，卡片进入／退出、步骤高亮和字幕才绑定对应语句；原脚本不能替代实际音频 |
| 本地渲染 | 带字幕、标题与素材的成片 | 开头卡可立即出现，后续卡随语义切换；保留自然停顿，音乐不盖过语音 |
| 质检／复核 | 成片和可追溯记录 | 低置信度、字幕估时、未核实事实显式记录；降级成简单字幕时也不得标成已对齐 |

在语音对齐接通以前，优先做整句／整段静态信息卡并复核时机，不宣传逐词卡点。剪切尾部静音不能证明正文每句同步。工具与供应商的更换放在流水线设置层，风格配方引用能力与素材，不绑定某一家付费模型。

## 8. 验收与迭代顺序

第一期先用已完成的真实原片做本地包装样例，再判断哪些配方确实需要新拍／新生成。文档、计划和渲染成功是不同证据，不能用文件存在代替成片检查。

- **懒人入口**：给六条典型一句话请求，系统能选到合理配方并给出可直接读的文案；除必需的真实性／素材问题外，不要求填写风格参数。
- **信息承诺**：mini 只讲一个点；标题承诺与正文吻合；情感内容有具体处境，知识内容有正确结论，故事有因果。
- **真实材料**：销售参数、体验、前后效果、资历、时间地点都可追溯；缺实物不伪造演示；虚构情节、数字人和素材性质清楚可见。
- **可观看**：实际播放检查语音、漏字、字幕和画面含义；解码首／中／末及每次卡片切换附近的画面，确认中文字幕不缺字、不遮脸／嘴、不超出目标平台安全区。
- **时间与连续性**：检查尾句没有被截断；未对齐仍显示估时；长版另验多段音色、身份、音量和节奏，不以片段拼接完成代替通过。
- **费用透明**：本地换包装不调用生成提供方；新片段、外部转写、配音、音乐或额外画面在执行前列出是否需要外部服务及额度／费用依据。没有依据时写“待核实”，不写“免费”。
- **效果评价**：先验收清楚、真实、可完成，再在获准发布后比较相似题材的观看保持、理解反馈和目标行动。记录题材、账号、发布时间等差异；不凭单条表现给配方贴“爆款”标签。

推荐交付顺序：库先设计六种，首轮只验证知识讲解、温暖共鸣、单卖点介绍三个代表，复用现有三种外观，补文案规则／语气与少量卡片；随后接实际语音对齐，再扩展另外三个默认和真实商品／录屏／现场素材的增强配方。优先接少量已有组件契约，不另建庞大编辑引擎。现阶段不追求几十种颜色皮肤，也不把未经验证的多角色生成列为默认能力。
